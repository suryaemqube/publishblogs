How failures are grouped

  • Blocker
    Nothing was written. The site rejected us at the first call, so there is no half-created post to clean up.
  • Partial
    The post exists but something is missing - an image, a term. The post ID is recorded so a retry can update rather than duplicate.
  • Advisory
    The post is live and correct, but Swan could not verify something it wanted to. Recorded, not raised as an error.

Retry safety

Retries are matched on slug, so retrying a partial failure updates the existing post instead of creating a second one. A retry that would create a duplicate asks first.

Rows that failed at authentication cannot be retried until someone stores a new Application Password for that site - Swan will not keep trying a credential it already knows is dead.
